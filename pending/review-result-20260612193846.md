## Gaps con CLAUDE.md

### [GAP] Busqueda web no aparece en modo emoji

- **CLAUDE.md dice**: "En modo emoji (query empieza por `:`), usa el texto tras `:` como termino de busqueda; si la query es solo `:`, el item no se muestra".
- **El codigo hace**: `WebSearchSource.cs:32` devuelve `[]` para cualquier query que empiece por `:`. No existe ninguna otra ruta que cubra ese caso, asi que el item de busqueda web nunca aparece en modo emoji.
- **Opciones**:
  - A) Implementar la rama documentada (extraer texto tras `:`, ocultar si la query es solo `:`)
  - B) El desarrollador actualiza CLAUDE.md si la intencion cambio

### [GAP] Paste automatico de emoji no funciona en Linux

- **CLAUDE.md dice**: la accion de emoji es "copiar al portapapeles + ocultar ventana + restaurar app anterior + simular paste".
- **El codigo hace**: `LinuxAppHandler` no overridea `SimulatePasteAsync`, hereda el no-op de `AppHandler.cs:145-149`. En Linux el paste nunca ocurre, sin log ni aviso.
- **Opciones**:
  - A) Implementar paste simulado en Linux (xdotool/wtype) o loguear "unsupported"
  - B) Documentar Linux como plataforma sin soporte de paste

### [GAP] UpdateChecker apunta a un endpoint placeholder

- **CLAUDE.md dice**: "Un UpdateChecker consulta un endpoint remoto para detectar nuevas versiones".
- **El codigo hace**: `UpdateChecker.cs:9` usa `example.com`. CheckAsync siempre falla y loguea un warning en cada arranque. Ademas `_http` (linea 11) nunca se libera.
- **Opciones**:
  - A) Configurar el endpoint real (o leerlo de config) y hacer la clase IDisposable
  - B) Desactivar el check hasta que exista endpoint

## Bugs

### Criticos

### [BUG] `new Uri("http://")` lanza UriFormatException en UrlSearch y ClipboardSearch

- **Fichero**: `Yottacast.Core/Search/Url/UrlSearch.cs:47` (y :120, :306), `Yottacast.Core/Search/Clipboard/ClipboardSearch.cs:97` (y :130)
- **Que ocurre**: `TryNormalizeUrl` acepta cualquier query que empiece por `http://` sin validar que haya host; el `new Uri(url).Host` posterior lanza.
- **Como reproducirlo**: teclear "http://" caracter a caracter (la septima pulsacion de cualquier URL escrita a mano). O copiar "http://" al portapapeles y mostrar la ventana: `ClipboardSearch.OnWindowShown` lanza dentro de `HandleWindowShownAsync` (`MainWindow.axaml.cs:126-132`, sin catch).
- **Impacto**: la excepcion sube por `GlobalSearch.SearchInstant` hasta el fire-and-forget del VM y mata en silencio la busqueda de ese keystroke; en la ruta de clipboard es una unobserved exception.
- **Fix sugerido**: en `TryNormalizeUrl` validar con `Uri.TryCreate(url, UriKind.Absolute, out var u) && !string.IsNullOrEmpty(u.Host)`.

### [BUG] Si el escaneo inicial de apps falla, la ventana no se muestra nunca

- **Fichero**: `Yottacast.Core/Search/Application/ApplicationSearch.cs:189-195`
- **Que ocurre**: `ScanAndWatchAsync` no tiene try/catch. Si `platform.ScanAppsAsync` lanza, `_readyTcs.TrySetResult()` no se ejecuta, `WhenInstantReady()` no completa y `ShowWhenInstantReadyAsync` (`App.axaml.cs:163`, fire-and-forget sin catch) deja la app arrancada sin UI ni log.
- **Como reproducirlo**: cualquier fallo de mdfind/SpotlightInterop o un TaskCanceledException temprano.
- **Impacto**: app zombie, el usuario tiene que matar el proceso.
- **Fix sugerido**: try/catch/finally con `TrySetResult` en finally y log del error.

### [BUG] IndexOutOfRange en busqueda de ficheros Linux con query de solo comillas o espacios

- **Fichero**: `Yottacast.Core/Platform/LinuxPlatformProvider.cs:106-107`
- **Que ocurre**: `safeQuery = query.Replace("\"", "")` y luego `tokens[0]` sin comprobar que haya tokens. Mac y Windows si guardan con `IsNullOrEmpty` tras sanear; Linux no.
- **Como reproducirlo**: query `""` (2 chars, pasa `FileSearchMinQueryLength=2`) o solo espacios.
- **Impacto**: excepcion sincrona en el pipeline de busqueda.
- **Fix sugerido**: `if (tokens.Length == 0) return Task.CompletedTask;`.

### [BUG] `async void` sin catch en PluginService puede derribar el proceso

- **Fichero**: `Yottacast.Core/Services/PluginService.cs:46-49` (y :55, :106)
- **Que ocurre**: `OnDirectoryChanged` es `async void`; cualquier excepcion de `ReloadAsync` (p.ej. `Directory.EnumerateFiles` fuera de todo try, o una excepcion de cualquiera de los 3 suscriptores de `PluginsChanged`, que ademas corren en el thread del FileSystemWatcher, no en UI thread) escala como unhandled y mata la app.
- **Como reproducirlo**: editar un plugin JSON mientras un suscriptor lanza.
- **Fix sugerido**: envolver el cuerpo completo en try/catch con log.

### [BUG] Lectura de Dictionary sin lock mientras se muta en PluginService

- **Fichero**: `Yottacast.Core/Services/PluginService.cs:25` (GetIcon) vs `:98-102` (ReloadAsync)
- **Que ocurre**: `GetIcon` lee `_icons` sin lock en cada busqueda (`WebSearchSource.cs:55`, threads de search) mientras `ReloadAsync` hace `Clear()` + escrituras bajo lock en thread pool. Lectura concurrente de un Dictionary en mutacion puede lanzar o devolver estado corrupto.
- **Fix sugerido**: `lock(_icons)` en GetIcon, o reemplazar el diccionario completo por referencia (como ya se hace con `Plugins`).

### [BUG] Crash en Windows al primer uso del cursor: P/Invoke con EntryPoint inexistente

- **Fichero**: `Yottacast/Services/WindowsAppHandler.cs:84-85`
- **Que ocurre**: `[DllImport("user32.dll")] static extern int ShowCursorWin(bool show);` sin `EntryPoint`. El export real es `ShowCursor`; la llamada lanza `EntryPointNotFoundException`.
- **Como reproducirlo**: en Windows, abrir el launcher y pulsar cualquier tecla (`MainWindow.OnTunnelKeyDown` llama `HideCursor()`).
- **Impacto**: excepcion no capturada en un event handler, crash.
- **Fix sugerido**: `[DllImport("user32.dll", EntryPoint = "ShowCursor")]`.

### [BUG] IPC: campo proto `clipboard_history_enabled` huerfano

## Inconsistencias

### [INCONSISTENCIA] LaunchHistory: doc y nombre de "half-life" no coinciden con la formula

- **Ficheros**: `Yottacast.Core/Services/LaunchHistory.cs:11, 52`, `AppDefaults.cs:71-72`
- **Que ocurre**: el doc dice "count x e^(-ageDays/halfLifeDays)" pero el codigo usa `log(count+1) x decay`; ademas `e^(-age/30)` reduce a la mitad a los ~20.8 dias, no a los 30 que promete AppDefaults.
- **Opciones**:
  - A) Usar `Math.Exp(-ageDays * Math.Log(2) / halfLife)` para que sea un half-life real
  - B) Corregir docs/comentarios para describir la formula actual
- **Recomendacion**: A, el setting promete un half-life y es lo que el usuario configura.
